LMS Course Booking — Project Report

Full codebase scan  ·  Branch: main  ·  No uncommitted changes

1 · Overview

A full-stack Learning Management System (LMS) for managing courses, students, bookings, enrollments, and training sessions. It exposes a REST API consumed by a single-page React application. The project is split into two independent workspaces: Back End (Laravel 13) and Front End (React 19 + TypeScript + Vite).

6 · Architecture & Design Decisions

Context Providers
  • AuthProvider — current user, role helpers (isAdmin, isInstructor, isStudent)
  • PreferencesProvider — theme + locale, persisted; wraps outside AuthProvider so the login page inherits it
  • ToastProvider — global toast notifications
API Layer (src/api/)
  • Centralised Axios client with Sanctum bearer token
  • auth, bookings, client, courses, dashboard, download, enrollments, notifications, students, trainingSessions, users
Internationalisation (i18n)

Full EN + AR translation via i18next + react-i18next. Language auto-detected from browser. Navigation labels are resolved inside the component (not at module level) to avoid freezing on language switch. RTL support via a CSS class driven by locale preference.

File Storage

Course files and student documents are stored on a private disk (not public storage). Downloads go through dedicated authenticated API routes (/courses/{course}/files/{file} and /students/{student}/documents/{document}). Course files are organised in per-course directories (course-{id}/) and cleaned up on hard delete via a model observer.

Dev Bypass Mode

Setting DEV_NO_AUTH=true in .env (and the matching Vite env var) bypasses Sanctum on the back end (DevAuthBypass middleware injects an admin) and skips the PrivateRoute guard on the front end. Login/register routes redirect to / automatically. Intended for local development only.

8 · Notable Observations

⚠ DB default is SQLite The .env.example ships with DB_CONNECTION=sqlite. MySQL config is commented out. The DashboardController handles both via a monthExpression() helper that switches between strftime and DATE_FORMAT.
⚠ Mail is log-only in dev MAIL_MAILER=log — booking confirmation emails are written to the log file, not sent. SMTP credentials must be configured for production.
✓ Strengths
  • Clean role-based access split across both the API route file and the React sidebar — they stay in sync by design.
  • Private file storage with authenticated download routes — no public asset leak risk.
  • Event-driven booking notifications (BookingCreated → in-app bell + confirmation email).
  • Full bilingual support (EN/AR) with RTL awareness.
  • Soft deletes on Courses and Bookings to preserve referential integrity.
  • Rate limiting on login, booking creation, and file uploads.
  • Dev auth bypass is isolated to a single middleware + env flag, with no production footprint.
△ Potential Gaps
  • No real payment gateway integration — payment_method / transaction_id are stored manually.
  • No email verification enforced at login (field exists but no gate).
  • No automated test coverage observed in tests/ beyond the default Laravel scaffolding.
  • Dashboard monthly revenue chart is rendered as plain text blocks, not a true SVG/canvas chart.
  • Student and User are separate models with no shared identity — a student cannot log in as a user by default.
