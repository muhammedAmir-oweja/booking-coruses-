Four defects to fix first

These are in the code right now. Two of them break a page outright — fixing them is folded into the phases below, but you should know what you're walking into.

Breaks page

The Register page calls an endpoint that doesn't exist

The frontend posts to /auth/register, but routes/api.php only registers /auth/login as a public route. Every sign-up attempt gets a 404.

Front End/src/api/auth.ts:8  →  Back End/routes/api.php:14–16

Breaks page

The dashboard query is MySQL-only, but the database is SQLite

DATE_FORMAT() does not exist in SQLite, and .env sets DB_CONNECTION=sqlite. Both monthly-trend queries throw, so GET /api/dashboard/stats — the app's landing page — returns a 500.

Back End/app/Http/Controllers/Api/DashboardController.php:62, 76

Dead route

Updating a booking hits a method that was never written

apiResource('bookings') points PUT/PATCH /bookings/{id} at BookingController@update. That method doesn't exist — the controller defines updateStatus() instead, and nothing routes to it. Marking a booking paid is currently impossible through the API.

Back End/routes/api.php:34  →  BookingController.php:69

Design gap

Non-admins can sign up into a wall of 403s

The register form lets people pick student or instructor, but every route except login sits behind admin middleware. Once registration works, those users log in successfully and then get 403 on literally every screen. Decide now: either registration creates admins only, or it stays invite-only and the form goes.

Back End/routes/api.php:18  →  Front End/src/pages/Register.tsx:129

Recommendation on the last one: keep registration open but force role = 'student' server-side (never trust the posted role), and leave the admin panel admin-only. The plan below does exactly that. Student-facing screens are a separate project.

The model

app/Models/OtpCode.php
<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\Relations\BelongsTo;

class OtpCode extends Model
{
    protected $fillable = [
        'user_id', 'purpose', 'code_hash', 'attempts', 'expires_at', 'consumed_at',
    ];

    protected function casts(): array
    {
        return [
            'expires_at'  => 'datetime',
            'consumed_at' => 'datetime',
        ];
    }

    public function user(): BelongsTo
    {
        return $this->belongsTo(User::class);
    }

    public function isExpired(): bool
    {
        return $this->expires_at->isPast();
    }

    public function isUsable(): bool
    {
        return ! $this->consumed_at && ! $this->isExpired();
    }
}

The service

Note the two defences that matter: a cooldown so the endpoint can't be used to spam somebody's inbox, and an attempt counter so a 6-digit code can't be brute-forced.

app/Services/OtpService.php
<?php

namespace App\Services;

use App\Models\OtpCode;
use App\Models\User;
use App\Notifications\SendOtpCode;
use Illuminate\Support\Facades\Cache;
use Illuminate\Support\Facades\Hash;
use Illuminate\Support\Str;

class OtpService
{
    /**
     * Generate a fresh code, store it hashed, and notify the user.
     * Returns the plain code for tests only — never put it in an API response.
     */
    public function issue(User $user, string $purpose = 'password_reset'): string
    {
        $this->invalidate($user, $purpose);

        $max  = (10 ** config('otp.length')) - 1;
        $code = str_pad((string) random_int(0, $max), config('otp.length'), '0', STR_PAD_LEFT);

        OtpCode::create([
            'user_id'    => $user->id,
            'purpose'    => $purpose,
            'code_hash'  => Hash::make($code),
            'expires_at' => now()->addMinutes(config('otp.ttl_minutes')),
        ]);

        $user->notify(new SendOtpCode($code, $purpose));

        Cache::put($this->cooldownKey($user, $purpose), true, config('otp.resend_cooldown'));

        return $code;
    }

    /** Check a submitted code, burning it on success. */
    public function verify(User $user, string $code, string $purpose = 'password_reset'): bool
    {
        $otp = OtpCode::where('user_id', $user->id)
            ->where('purpose', $purpose)
            ->whereNull('consumed_at')
            ->latest('id')
            ->first();

        if (! $otp || ! $otp->isUsable()) {
            return false;
        }

        if ($otp->attempts >= config('otp.max_attempts')) {
            return false;
        }

        $otp->increment('attempts');

        if (! Hash::check($code, $otp->code_hash)) {
            return false;
        }

        $otp->forceFill(['consumed_at' => now()])->save();

        return true;
    }

    /** True while the resend cooldown is still running. */
    public function onCooldown(User $user, string $purpose = 'password_reset'): bool
    {
        return Cache::has($this->cooldownKey($user, $purpose));
    }

    /** Burn every outstanding code — called before issuing a new one. */
    public function invalidate(User $user, string $purpose = 'password_reset'): void
    {
        OtpCode::where('user_id', $user->id)
            ->where('purpose', $purpose)
            ->whereNull('consumed_at')
            ->update(['consumed_at' => now()]);
    }

    /** Short-lived ticket proving a code was verified, so reset doesn't resend it. */
    public function issueResetTicket(User $user): string
    {
        $ticket = Str::random(64);

        Cache::put("otp:ticket:{$ticket}", $user->id, now()->addMinutes(10));

        return $ticket;
    }

    public function consumeResetTicket(string $ticket): ?User
    {
        $userId = Cache::pull("otp:ticket:{$ticket}");

        return $userId ? User::find($userId) : null;
    }

    private function cooldownKey(User $user, string $purpose): string
    {
        return "otp:cooldown:{$purpose}:{$user->id}";
    }
}

The notification

One notification class, delivered on two channels: mail for the human, database so you have an audit trail of every code that went out.

bash
php artisan make:notification SendOtpCode
php artisan vendor:publish --tag=laravel-mail   # optional: to restyle the email shell
app/Notifications/SendOtpCode.php
<?php

namespace App\Notifications;

use Illuminate\Bus\Queueable;
use Illuminate\Contracts\Queue\ShouldQueue;
use Illuminate\Notifications\Messages\MailMessage;
use Illuminate\Notifications\Notification;

class SendOtpCode extends Notification implements ShouldQueue
{
    use Queueable;

    public function __construct(
        public string $code,
        public string $purpose = 'password_reset',
    ) {}

    public function via(object $notifiable): array
    {
        return ['mail', 'database'];
    }

    public function toMail(object $notifiable): MailMessage
    {
        $minutes = config('otp.ttl_minutes');

        return (new MailMessage)
            ->subject("Your verification code is {$this->code}")
            ->greeting("Hello {$notifiable->name},")
            ->line($this->intro())
            ->line('**'.$this->code.'**')
            ->line("The code expires in {$minutes} minutes and can be used once.")
            ->line('If you did not ask for this, no action is needed — your account is unchanged.')
            ->salutation('— '.config('app.name'));
    }

    public function toArray(object $notifiable): array
    {
        return [
            'purpose' => $this->purpose,
            'sent_at' => now()->toDateTimeString(),
        ];
    }

    private function intro(): string
    {
        return match ($this->purpose) {
            'password_reset' => 'Enter this code to reset your password.',
            'email_verify'   => 'Enter this code to confirm your email address.',
            default          => 'Enter this code to continue.',
        };
    }
}
Never put the code in the subject line in production. It's convenient while MAIL_MAILER=log, but subject lines show up on lock screens and in notification previews. Before you ship, change it to a plain 'Your verification code'.

Controller methods

Two rules drive the design here. Registration never trusts the posted role — it's hardcoded to student. And forgot-password always returns the same 200, whether or not the email exists, so the endpoint can't be used to discover who has an account.

app/Http/Controllers/Auth/AuthController.php — add these
use App\Facades\Otp;
use App\Http\Requests\Auth\ForgotPasswordRequest;
use App\Http\Requests\Auth\RegisterRequest;
use App\Http\Requests\Auth\ResetPasswordRequest;
use App\Http\Requests\Auth\VerifyOtpRequest;
use App\Models\User;

public function register(RegisterRequest $request): JsonResponse
{
    $user = User::create([
        'name'     => $request->name,
        'email'    => $request->email,
        'password' => Hash::make($request->password),
        'role'     => 'student',   // never from the request body
    ]);

    return response()->json([
        'token' => $user->createToken('api-token')->plainTextToken,
        'user'  => $user,
    ], 201);
}

public function forgotPassword(ForgotPasswordRequest $request): JsonResponse
{
    $user = User::where('email', $request->email)->first();

    // Always the same answer — do not leak whether the account exists.
    if ($user && ! Otp::onCooldown($user)) {
        Otp::issue($user);
    }

    return response()->json([
        'message'          => 'If that email is registered, a verification code is on its way.',
        'expires_in'       => config('otp.ttl_minutes') * 60,
        'resend_available' => config('otp.resend_cooldown'),
    ]);
}

public function resendOtp(ForgotPasswordRequest $request): JsonResponse
{
    $user = User::where('email', $request->email)->first();

    if ($user && Otp::onCooldown($user)) {
        return response()->json([
            'message' => 'A code was sent recently. Please wait before requesting another.',
        ], 429);
    }

    if ($user) {
        Otp::issue($user);
    }

    return response()->json(['message' => 'If that email is registered, a new code is on its way.']);
}

public function verifyOtp(VerifyOtpRequest $request): JsonResponse
{
    $user = User::where('email', $request->email)->first();

    if (! $user || ! Otp::verify($user, $request->code)) {
        return response()->json([
            'message' => 'That code is invalid or has expired.',
            'errors'  => ['code' => ['That code is invalid or has expired.']],
        ], 422);
    }

    return response()->json([
        'message'      => 'Code verified.',
        'reset_token'  => Otp::issueResetTicket($user),
        'expires_in'   => 600,
    ]);
}

public function resetPassword(ResetPasswordRequest $request): JsonResponse
{
    $user = Otp::consumeResetTicket($request->reset_token);

    if (! $user) {
        return response()->json([
            'message' => 'This reset link has expired. Please start again.',
            'errors'  => ['reset_token' => ['This reset link has expired. Please start again.']],
        ], 422);
    }

    $user->update(['password' => Hash::make($request->password)]);
    $user->tokens()->delete();   // sign out every device after a reset

    return response()->json(['message' => 'Password updated. You can sign in now.']);
}

<?php

namespace App\Http\Resources;

use Illuminate\Http\Request;
use Illuminate\Http\Resources\Json\JsonResource;

class CourseResource extends JsonResource
{
    public function toArray(Request $request): array
    {
        return [
            'id'             => $this->id,
            'title'          => $this->title,
            'description'    => $this->description,
            'instructor_id'  => $this->instructor_id,
            'instructor'     => $this->whenLoaded('instructor', fn () => [
                'id'   => $this->instructor->id,
                'name' => $this->instructor->name,
            ]),
            'price'          => (float) $this->price,
            'capacity'       => $this->capacity,
            'hours'          => $this->hours ?? 0,
            'enrolled_count' => $this->enrollments_count ?? 0,
            'status'         => $this->status,
            'start_date'     => $this->start_date?->toDateString(),
            'end_date'       => $this->end_date?->toDateString(),
            'created_at'     => $this->created_at,
        ];
    }
}

public function index(Request $request)
{
    $courses = Course::with('instructor')
        ->withCount('enrollments')
        ->when($request->filled('search'), fn ($q) =>
            $q->where('title', 'like', '%'.$request->search.'%'))
        ->when($request->filled('status'), fn ($q) =>

        ->paginate(min((int) $request->get('per_page', 10), 200));

One breaking difference to watch. Resource::collection($paginator) nests pagination under a meta key, while the current controllers return Laravel's flat paginator shape (current_page, last_page, total at the top level) — which is what PaginatedResponse<T> in the frontend expects. Either keep the flat shape with JsonResource::withoutWrapping() in a service provider, or update Front End/src/types/index.ts. Pick one before you convert all seven.

Facade map

Which facade does what in this codebase, and where each one is called. Otp is the one you're building; the rest ship with Laravel.

FacadeImportUsed for
OtpApp\Facades\OtpYours. Issue, verify, invalidate codes; mint and consume reset tickets
AuthSupport\Facades\AuthAuth::attempt() on login, Auth::user() for the current user
HashSupport\Facades\HashHashing passwords and OTP codes; Hash::check() on verify
CacheSupport\Facades\CacheResend cooldown and reset tickets — backed by the DB store
DBSupport\Facades\DBDB::raw() in the dashboard aggregates; driver detection for the SQLite fix
StorageSupport\Facades\StorageDeleting student photos and documents from the public disk
NotificationSupport\Facades\NotificationNotification::fake() in tests to assert an OTP was sent
SchemaSupport\Facades\SchemaEvery migration
Why a facade instead of injecting OtpService? Both work. The facade wins here because OTP logic is called from a handful of unrelated places and reads better inline (Otp::verify($user, $code)), and because Otp::swap() / Otp::shouldReceive() makes it trivial to stub in tests. If you later need per-tenant OTP config, switch to constructor injection — the service class doesn't change.

API contract

All 49 endpoints — URL, method, who can call it, what goes in, what comes back. New marks what this plan adds; Broken marks what's defective today.

Conventions

  • Base URL — http://localhost:8000/api (frontend reads VITE_API_URL)
  • Auth — Authorization: Bearer <token>. Every route tagged admin needs a token and role === 'admin', else 403.
  • Headers — Accept: application/json on everything; Content-Type: multipart/form-data for the two upload endpoints, JSON elsewhere.
  • Validation errors — 422 with { message, errors: { field: [msg] } }
  • List endpoints — all accept ?page and ?per_page (default 10, capped at 200), and return the flat paginator envelope below.
Paginated envelope
every list response
{
  "current_page": 1,
  "data": [ /* items */ ],
  "last_page": 4,
  "per_page": 10,
  "total": 37
}
Error shapes
401 / 403 / 422
{ "message": "Unauthenticated." }

{ "message": "Forbidden. Admin access required." }

{ "message": "The email field is required.",
  "errors": { "email": ["The email field is required."] } }
